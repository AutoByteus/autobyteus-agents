# Design

How this project is built and the design rules a change here follows. Read it
before designing a solution, architecture or refactor, and during
implementation and review. It holds what is specific to this project; general
design practice is not repeated here.

Keep each section to what someone designing a change here needs; delete a
section that does not apply.

## Architecture Overview

The main parts (applications, packages, services, subsystems), what each owns
and where it lives, how they depend on each other, and the main flows through
them.

## Conventions

The rules the code follows, each with its reason when the reason is known: for
example error handling, configuration, persisted data and migrations, naming,
file layout, and the libraries or patterns to use or avoid.

## Project Design Documents

Deeper design documents or contracts for particular areas, each with when to
read it.
