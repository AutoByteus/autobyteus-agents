I stopped before designing or coding anything. A bug in the existing code has to be fixed first, and one decision needs you.

**What I found:** mini-mcp never sends any configured headers. `src/mcp-client.js` passes `{ headers }` to the SDK, but `tiny-mcp-sdk` 1.2.0 only reads `requestInit.headers`, so the header is silently dropped.

I checked this against the real SDK, not the fake used in the test:
- With `Authorization: Bearer tok` configured, the request preview shows `headers: {}`.
- Passing it as `requestInit: { headers }` instead does send it.
- `node test/mcp-client.test.js` still prints PASS, because it replaces the SDK with a fake that records whatever it is given.

**Why it comes first:** a Jira preset can't meet "requests carry the header" while this bug exists. The bug is in how the transport is built, not in the Jira preset, so I'm treating it as a prerequisite rather than part of this ticket. I haven't created a Task for it, since there's no Project Task Manager here.

**What I need from you:**
1. Is it OK to fix the header bug first, as its own small change? The fix is passing `requestInit: { headers }`, plus a test that uses the real SDK instead of the fake. After that I'd continue with the Jira preset in the same package.
2. Where should the token live? I recommend a reference like `${JIRA_API_TOKEN}` that is read from the environment, because `mcps.json` is tracked in git and an inline token would get committed. The alternative is putting the token directly in `mcps.json`.

The requirements are Blocked, not approved, until the prerequisite is delivered and you answer the token question.
